# Lab 9: Watching System Calls with strace

[Original PDF](Lab9_Luchiciov_Alexei_Reitman_Patricia.pdf) · [Read on GitHub](report.md) · [Editable DOCX](report.docx)

Linux file I/O and observing `openat`, `read`, `write` and `close` with `strace`.

## Files

- [syscalls.c](syscalls.c): writes and reads `hello, kernel\n` using file descriptors.
- [commands.sh](commands.sh): reproduces the three tracing exercises in a fresh temporary directory and prints its location.
- [Makefile](Makefile): build and test targets for Linux.
- [tests/test.sh](tests/test.sh): verifies file truncation, the exact 14-byte result and the corresponding trace entries.
- [notes.md](notes.md): observed counts and explanation of file descriptors.

## Run in Ubuntu

Requirements: a C compiler, Make, Bash, coreutils and **Linux strace**.

```bash
make
./syscalls
cat note.txt
bash commands.sh
make test
```

`./syscalls` creates or truncates `note.txt` in the current directory. `commands.sh` uses its own temporary directory and leaves the output/trace files there for inspection. `make test` uses a separate temporary directory and removes its generated artifacts.

The actual syscall counts depend on the Linux installation, C library, locale and directory contents. The counts in the PDF are historical observations. The test checks the file's bytes and its traced operations instead of requiring those historical counts. The similarly named MSYS tracing tool supplied with Git for Windows does not provide Linux `strace` behavior.
